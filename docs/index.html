小程序生产交付指南

把“需求做出来”变成“可以稳定上线、可验收、可维护”的应用。

需求应当描述业务闭环

每项需求应明确操作者、触发条件、处理规则、成功结果和失败反馈。以下单为例，除提交入口外，还应覆盖库存不足、重复提交、价格变化、支付超时、取消和退款。

关键规则由服务端验证

  • 价格、优惠、运费和库存以服务端重新计算为准。
  • 订单、库存与支付回调需要一致性和幂等处理。
  • 接口按用户、门店和角色做数据权限校验。

上线前至少覆盖这些异常

场景预期
重复提交只生成一条有效记录
网络超时有明确提示与安全重试入口
登录过期清理失效会话并引导重新认证
无权限访问服务端拒绝且不泄露数据

交付证据

每次上线保留版本号、数据变更、接口变更、回滚步骤和关键流程测试记录。操作日志应包括请求标识、时间、操作者和状态变化。

项目评估

预览可复用小程序项目时，应实际走通登录、创建、查询、修改、取消和后台处理流程。可以在 Togtok 应用开发与项目广场 查看可预览项目，并按本指南核对其交付能力。
